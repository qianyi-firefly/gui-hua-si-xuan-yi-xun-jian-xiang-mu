# 实机验收交接

状态：仿真完整验收尚未结束，实机未验证。本文件记录仿真到实机的必需差异；通过有限仿真测试不表示真实飞行已通过。

## 数据与坐标

- ROS 使用 ENU、机体 FLU。Faster-LIO 位姿经过雷达/IMU到机体中心外参和世界旋转后送 `/mavros/odometry/out`，由 MAVROS 执行协议坐标转换。禁止额外手动转为 NED。
- EGO 使用 PX4 本地 ENU 里程计和速度。障碍点云通过同采集时刻附近的 LIO/FCU 位姿映射到相同的 FCU 本地 ENU 数值坐标，不能仅因为两边 frame_id 同名就认为原点相同。
- 只融合外部位置/高度/航向，不融合外部速度。外部消息的未知速度协方差为 1e6；期望轨迹速度是控制前馈，与 EKF 测量速度无关。
- PX4 IMU 必须继续参与状态传播与速度估计。不能在 EKF 中字面上移除其对位置传播的影响。

## 实机阶段验收顺序

1. 桨不转的数据检查：LiDAR/独立 IMU、两相机、ENU轴与姿态、机体中心外参、TF、EV消息时间和协方差、相同坐标系中的点云/FCU轨迹、UI健康与按钮状态。
2. 静止及手动移动：检查 LIO 位姿连续性、Z/姿态约束、点云遮挡、PX4 ULog 融合标志和位置残差；确认定位失效不会被旧健康消息掩盖。
3. 受控起飞/悬停/一键降落：验证授权流程、持续 OFFBOARD 目标流和上锁；记录真值参考/机上日志，按仿真门槛及实机条件判定。
4. 低速局部规划：先空旷单目标，再静态障碍与返程；确认前倾雷达盲区的障碍记忆与实际机体包络。
5. 逐项验证实机故障处理、通信链路和人工接管路径。仿真的节点退出/丢包结果不能替代真实串口断开、进程卡死、供电或现场网络故障验证。

最终仿真通过报告应引用同一生产指纹的完整核心、17项扩展、bag/ULog、UI证据和归档。实机通过必须另建实验报告，不回写仿真数据作为实机证明。
